# Skills

Generated by `scripts/build_docs.py` from each skill's `SKILL.md`.

## Ingest: `spotfire-ingest`

Read existing work (app prototypes, Excel calculation workbooks) and write the App Brief, Logic Spec and build spec that the build skills use.

Install: `/plugin install spotfire-ingest@fde-spotfire-ai-skills`

### `ingesting-excel-workbooks`

Breaks down an engineering calculation workbook (.xlsx or .xlsm) without running it, documents its structure, calculations, issues and purpose, reproduces its numbers in a Python model reconciled against the workbook's values, and writes the App Brief, Logic Spec, draft build spec, change list and data function code for a Spotfire DXP. Ships the inventory, R1C1 block, dependency, issue scan, dossier, model scaffold and reconciliation scripts, with owner checkpoints after the meaning, the model and the redesign. Use it when a spreadsheet tool must become a Spotfire analysis, when a workbook needs an audit of its formulas before anyone relies on it, or when the build step needs the reconciliation script. It never builds the DXP; the building-spotfire-dxps skill reads its files.

Alpha status: New, not yet tested. Source: [plugins/spotfire-ingest/skills/ingesting-excel-workbooks](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-ingest/skills/ingesting-excel-workbooks)

### `ingesting-prototypes`

Reads an app prototype (Shiny for Python, Streamlit, Plotly or Dash, Quarto, plain HTML or a React mockup) and writes the hand-off files for a Spotfire build, which are the App Brief, the Logic Spec, a draft spec.json and a mapping table that gives every prototype element its Spotfire element, with a named substitute for anything Spotfire has no direct equivalent for. Ships a scanner that inventories the prototype's pages, inputs, outputs and reactivity, and a check for the hand-off files. Use it when a prototype, dashboard or mockup must become a Spotfire analysis, before any DXP is built. It only reads and documents; it never builds a DXP.

Alpha status: New, not yet tested. Source: [plugins/spotfire-ingest/skills/ingesting-prototypes](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-ingest/skills/ingesting-prototypes)

## Design: `spotfire-design`

Decide what a Spotfire analysis must do for its users and how it behaves: App Brief framing, design rules and packaging.

Install: `/plugin install spotfire-design@fde-spotfire-ai-skills`

### `framing-spotfire-apps`

Writes the App Brief for a Spotfire analysis, starting with the business problem (who has it, what it costs, how it is handled today) before any capability, then users, decisions, KPIs, inputs, outputs, data sources and refresh cadence. Interviews the app owner with a fixed question set, reserves Logic Spec IDs for every KPI, and checks the brief before the build starts. Use it when someone asks for a new Spotfire app, dashboard or analysis, when an idea or a generic capability (anomaly detection, forecasting, a time series toolkit) needs a business problem, or when an App Brief written by an ingest skill must be completed and confirmed with its owner.

Alpha status: New, not yet tested. Source: [plugins/spotfire-design/skills/framing-spotfire-apps](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-design/skills/framing-spotfire-apps)

### `packaging-spotfire-apps`

Packages a Spotfire analysis so that people other than its author can find, open, understand and trust it. Defines the parts of a delivered app (DXP with embedded data, cover page, working pages, Method and Guide pages, data staging for users' own data, Data Generation page, release notes, setup and data guide, screenshots, article), the page order, the content of the cover and Method pages from the App Brief and Logic Spec, and a publishing checklist covering library location and descriptions, naming, leftover pages and tables, local paths, clean-machine and Web Player tests, screenshots and the article. Use it when an analysis is about to be handed over, published to a Spotfire library or shared with another team or customer, or when someone asks what a finished Spotfire app must include.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-design/skills/packaging-spotfire-apps](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-design/skills/packaging-spotfire-apps)

### `spotfire-app-design-rules`

Applies the design rules for how a Spotfire analysis behaves for its users. KPI bands built in HTML instead of KPI charts, marking that drives every relevant visual, no empty visuals, a filter panel limited to each page's user columns and never styled, controls next to the visuals they drive, a separate Data Generation page, operator what-if scenarios, short steps with Details and KPI popups, a Method page that explains the model, customer-ready text including code comments, a native Spotfire look, consistent units and colors, sanitizer-safe HTML. Each rule comes with why and how to check it; a script checks customer-ready text. Use it when designing the pages of a new analysis from its App Brief, reviewing a build spec or a built DXP before hand-over, or when a user reports that marking, filters, controls or text behave or read wrongly.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-design/skills/spotfire-app-design-rules](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-design/skills/spotfire-app-design-rules)

## Build: `spotfire-build`

Produce a Spotfire DXP and its parts through the Spotfire API: generated IronPython builders, data functions, IronPython scripts, styling, visualization mods and action mods.

Install: `/plugin install spotfire-build@fde-spotfire-ai-skills`

### `building-action-mods`

Builds and reviews Spotfire action mods (Spotfire 15.0, action API 2.5) in plain JavaScript. Covers the manifest, script files with RegisterEntryPoint, typed parameters, .NET interop from JavaScript, icons, wiring scripts to text-area buttons and to visual floating, title-bar and context-menu buttons, splitting work with IronPython property triggers, and connecting, updating and publishing the mod. Ships a tested four-script example with a type check against the official typings, a mock-based scenario test and a manifest checker. Use when creating, fixing, testing or wiring an action mod, adding buttons to visuals, or replacing IronPython buttons with action-mod scripts.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-build/skills/building-action-mods](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-build/skills/building-action-mods)

### `building-spotfire-dxps`

Builds a finished Spotfire Analyst DXP from an app spec through Spotfire's public API. Reads the App Brief, Logic Spec and draft spec.json that the ingest skills write (or writes spec.json from a request), exports the data to SBDF with Spotfire's own Python, validates the spec, generates one pasteable IronPython builder, has it run in Analyst 15.0 (by hand or unattended), verifies the saved DXP against the spec, lists what must be added by hand, and keeps every handover as a versioned release. Use when an app, a prototype hand-off or a workbook hand-off must become a DXP, when a DXP must be rebuilt from its spec, or when a saved DXP must be checked against its spec.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-build/skills/building-spotfire-dxps](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-build/skills/building-spotfire-dxps)

### `building-visualization-mods`

Builds and reviews Spotfire visualization mods in plain JavaScript. Covers choosing the mod API version, manifest rules that field clients enforce, the render loop and signalRenderComplete, marking, tooltips, popout pitfalls, theming from the Spotfire canvas, layers (API 2.4) and configuring mod visuals and layers from IronPython, plus a headless jsdom test harness and a manifest checker. Ships a working mod with three layers, synthetic data and its test. Use when creating, fixing, testing or packaging a Spotfire visualization mod, or when a mod renders wrongly, stops exporting, loses marking or is refused by a client.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-build/skills/building-visualization-mods](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-build/skills/building-visualization-mods)

### `styling-spotfire-dxps`

Styles Spotfire analyses (DXP files) without touching the filter panel or the data canvas. Ships a small stylesheet injector attached to one host text area per page, a matching theme JSON for visual titles and canvas, sanitizer-safe HTML snippets (side panel, KPI band, settings card, tabs, status legend, method panel), a palette with measured contrast and layout weights, plus offline checks for Spotfire's HTML sanitizer, a browser preview builder and a contrast checker. Use when styling or restyling a DXP, writing HTML for Spotfire text areas, building a KPI band, or when text areas look unstyled or lose controls on another machine.

Alpha status: New, not yet tested. Source: [plugins/spotfire-build/skills/styling-spotfire-dxps](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-build/skills/styling-spotfire-dxps)

### `writing-spotfire-data-functions`

Writes and reviews Python data functions for Spotfire Analyst. Covers the staging blocks that let one file run standalone and inside Spotfire, registration tables for the data function dialog, SBDF-safe output types (including text columns under pandas 3), shared outputs across sibling functions, customer staging functions and run chains, and ships a checker that runs a function and exports its outputs with Spotfire's own SBDF writer. Use when writing, fixing or reviewing any Python script that runs as a Spotfire data function, or when a data function output table is missing or has the wrong column types.

Alpha status: Proven on one machine. Source: [plugins/spotfire-build/skills/writing-spotfire-data-functions](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-build/skills/writing-spotfire-data-functions)

### `writing-spotfire-ironpython`

Writes and reviews IronPython 3.4 scripts for Spotfire Analyst documents. Covers document properties (creating, reading, writing), button scripts with parameters, page navigation, property-change triggers, data function run chains, transactions and the compile-once pattern that makes trigger-driven pages fast, and ships a linter for IronPython 3.4 syntax and a stub generator. Use when writing, fixing, speeding up or reviewing any script that uses the Spotfire.Dxp API inside an analysis, including scripts behind text-area buttons and property triggers.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-build/skills/writing-spotfire-ironpython](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-build/skills/writing-spotfire-ironpython)

## Testing and automation: `spotfire-testing`

Run Spotfire Analyst unattended and test DXPs through the user interface with window screenshots after each step. Windows only.

Install: `/plugin install spotfire-testing@fde-spotfire-ai-skills`

### `running-spotfire-unattended`

Runs IronPython builders and job scripts in a separate, unattended Spotfire Analyst instance on Windows, saves the resulting DXP and renders every page to PNG, with a lock so that runs do not collide. Use when a DXP must be built, rebuilt, re-rendered or changed through the Spotfire API without anyone clicking in Analyst, while the user's own open Analyst session stays untouched.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-testing/skills/running-spotfire-unattended](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-testing/skills/running-spotfire-unattended)

### `testing-dxps-through-the-ui`

Tests a Spotfire DXP through the Analyst user interface on Windows. Opens the analysis in its own Analyst instance, clicks tabs, buttons and visuals, marks items, takes a window-only screenshot after each step and checks the result, for example that a marking updates every visual it should. Also captures, crops and redacts screenshots for documentation. Use when a built or changed DXP must be checked the way a user works with it, or when documentation screenshots of an analysis are needed.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-testing/skills/testing-dxps-through-the-ui](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-testing/skills/testing-dxps-through-the-ui)

## Version control and CI/CD: `spotfire-version-control`

Update, track, check and compare DXPs with Git: automated data function updates, readable DXP diffs, CI on pull requests and library audits.

Install: `/plugin install spotfire-version-control@fde-spotfire-ai-skills`

### `auditing-and-comparing-dxps`

Audits Spotfire DXP files without opening Spotfire. Inventories pages, visuals, data functions, scripts, triggers, document properties, tables, markings and colors; compares two versions of an analysis; and checks a whole library folder against design and hygiene rules, grouping file versions and diffing consecutive ones. Use when a user asks what is in a DXP, what changed between two versions, whether analyses follow the design rules, or to review a folder of analyses before a release or a rebuild.

Alpha status: Proven on one machine. Source: [plugins/spotfire-version-control/skills/auditing-and-comparing-dxps](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-version-control/skills/auditing-and-comparing-dxps)

### `setting-up-dxp-ci`

Sets up GitHub Actions for Spotfire DXPs whose data function scripts are tracked in Git. Validation runs on GitHub-hosted runners for every pull request; status and push jobs run on a self-hosted runner labelled spotfire that can reach the DXPs; headless Claude Code runs keep the human approval step in CLAUDE.md. Ships workflow templates with placeholders. Use when a user wants pull request checks, required status checks or automated syncing for DXP data functions, or wants Claude Code to handle change requests from CI.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-version-control/skills/setting-up-dxp-ci](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-version-control/skills/setting-up-dxp-ci)

### `tracking-dxps-in-git`

Tracks Spotfire DXP files and their data function scripts in Git with dxpkit. Extracts a DXP into readable files, sets up a readable git diff for .dxp files, maps scripts to data functions in dxpkit.yaml, and keeps Git and the DXPs in sync with dxp status, push and pull, where the dxpkit.lock file catches edits made inside Spotfire. Use when a user wants DXPs or data function scripts under version control, wants to see what changed inside a DXP, or finds that Git and an analysis disagree.

Alpha status: Proven on one machine. Source: [plugins/spotfire-version-control/skills/tracking-dxps-in-git](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-version-control/skills/tracking-dxps-in-git)

### `updating-data-functions-with-claude`

Updates the Python script of a Spotfire data function from a Git project. Edits the function file, applies it through the Spotfire API in a staging copy of the DXP inside an unattended Analyst instance, runs it, renders every page and writes a report; a person approves the promotion, then the change is committed and pushed. Use when a user asks to change, fix or extend a data function in a DXP, or to set up a project where Claude Code or an IDE changes data functions without opening Analyst.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-version-control/skills/updating-data-functions-with-claude](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-version-control/skills/updating-data-functions-with-claude)

## Domain context: `spotfire-domain-context`

Engineering knowledge for understanding an app's goal and checking its results: process time series analysis, midstream unit knowledge, synthetic process data and analytics models.

Install: `/plugin install spotfire-domain-context@fde-spotfire-ai-skills`

### `analyzing-process-time-series`

Analyzes process and pipeline historian time series with a tested Python engine (tssme) that conditions every comparison on operating regime, corrects significance for autocorrelation, detects historian artifacts (frozen tags, transmitter rails, zero-order-held lab values, join duplicates, snapshot rows), evaluates unit card invariants, excludes confounders and matches multi-tag failure signatures. Use when deciding whether a trend, step, anomaly or model residual in sensor data is real, when reviewing an analysis or a Spotfire app's results for statistical faults, or when writing unit cards, tag maps and calibration overlays for the engine. Runs from the command line or inside a Spotfire Python data function.

Alpha status: Proven on one machine. Source: [plugins/spotfire-domain-context/skills/analyzing-process-time-series](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-domain-context/skills/analyzing-process-time-series)

### `generating-synthetic-process-data`

Generates synthetic process historian data from first principles for demos, tests and anomaly-detection training sets, using a three-layer simulator (environment, operations state machine, equipment physics), Ornstein-Uhlenbeck coloured noise, slow drift, perturbation texture and an event catalog whose expected signatures are verified after generation. Covers train and holdout splits, Spotfire-ready outputs (event stamp columns, tag pivots, data function packaging) and scaling out to Databricks or Snowflake. Use when building or reviewing a simulator or synthetic dataset for pumps, pipelines, compressors, columns, exchangers, wells or chemical units, or when demo data must look like a real plant historian.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-domain-context/skills/generating-synthetic-process-data](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-domain-context/skills/generating-synthetic-process-data)

### `midstream-process-knowledge`

Provides process engineering knowledge for midstream oil and gas units as YAML unit cards plus a process reference, covering crude pump stations (validated card), amine treating, TEG dehydration, cryogenic NGL recovery and Y-grade fractionation (draft cards pending SME review). Each card states the unit's measurement roles, the quantity that carries a finding, invariants, operating regimes, confounders and failure modes with multi-tag signatures. Use when working out what a midstream unit's sensors should be doing, when checking whether an app's or analysis's conclusion about such a unit is physically plausible, or when writing or reviewing a unit card. Cards are a knowledge pack for the analyzing-process-time-series skill, which validates them and turns them into checks.

Alpha status: Pump station card proven on one machine; four draft cards new, not yet tested. Source: [plugins/spotfire-domain-context/skills/midstream-process-knowledge](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-domain-context/skills/midstream-process-knowledge)

### `process-analytics-models`

Builds and reviews analytics models for process and production data that are delivered as Spotfire data functions, including interpretable regression suites (OLS with VIF, PLS1 by NIPALS with VIP, gradient boosted trees with permutation importance and ICE), anomaly detection (an LSTM autoencoder written in NumPy so it runs without torch, Isolation Forest and PCA baselines), forecasting with simulated paths, operation libraries over time series and events, and backtesting with strict holdout and event-level scoring. Use when writing or checking a model, a detector or its evaluation for an app, especially when it must run inside Spotfire's bundled Python.

Alpha status: Assembled from proven parts, not run as a whole. Source: [plugins/spotfire-domain-context/skills/process-analytics-models](https://github.com/josesilvestre-spotfire/fde-spotfire-ai-skills/tree/main/plugins/spotfire-domain-context/skills/process-analytics-models)
